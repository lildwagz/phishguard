Arsitektur Sistem PhishGuard

Deteksi SMS/Email phishing · Flutter (Android & Web) → REST API FastAPI → AI service (TF-IDF + Logistic Regression + lapisan aturan) · Docker

PENGGUNA

Menempel/mengetik pesan, memilih teks di aplikasi lain, atau membagikan SMS/WhatsApp lewat menu Bagikan

FLUTTER CLIENT

Android (APK) & Web
• layar utama: input, validasi kosong, kartu hasil + alasan
• popup Scan dengan PhishGuard dari seleksi teks (PROCESS_TEXT) & menu Bagikan (SEND)
• riwayat lokal (shared_preferences)

REST API (FastAPI)

GET /health · POST /v1/predict
• validasi Pydantic: wajib, tidak kosong, ≤ 2.000 karakter (422)
• rate limit 60/menit/IP (429)
• body ≤ 32 KB (413)
• CORS hanya origin web
• response: label, confidence, model_version, latency_ms, reasons

AI SERVICE (inference)

Model: pipeline TF-IDF kata 1–2 gram + karakter 3–5 gram → Logistic Regression (class_weight balanced), file phishguard.joblib, dimuat sekali saat start
Lapisan aturan (rules.py): file .apk, minta kode OTP, kerja dibayar per tugas, domain tiruan brand
Keputusan: phishing jika model ≥ 0,5 atau aturan terpicu

DATA / LOG

Log hanya: panjang teks, label, confidence, aturan, latency.
Isi pesan tidak disimpan & tidak di-log (NFR-03)

DEPLOYMENT + MONITORING

Docker Compose: container api (python:3.14-slim, port 8000, HEALTHCHECK /health) + web (nginx, port 8080)
Monitoring: latency_ms & model_version di setiap response, log container
Rencana cloud: Docker Space/PaaS (materi P6) dengan HTTPS

TRAINING (offline, bukan di aplikasi)

data/raw (Mendeley smishing EN, Rahmi & Wibisono ID, bopbi, kutipan berita 2022+) → prepare_dataset.py → train/test 80/20 → train.py (bandingkan NB vs LogReg, 5-fold CV) → model/phishguard.joblib + metrics.json

Ketertelusuran: FR-01/FR-04 (hasil + alasan) · FR-02 (validasi 422) · FR-03 (riwayat lokal) · FR-05/FR-06 (seleksi teks & Bagikan) · NFR-01 latency (latency_ms) · NFR-03 (log tanpa isi pesan, 429/413)
