# Plan: Dataset SMS phishing (langkah 1 di README)

Tanggal: 2026-11-12 · Status: **sedang dikerjakan**

## Tujuan
Siapkan dataset publik untuk melatih klasifikasi biner **Phishing vs Aman** (target akurasi ≥85%, NFR-03),
idealnya mencakup SMS **bahasa Indonesia** (pengguna PhishGuard = orang Indonesia).

## Kandidat sumber
| # | Dataset | Bahasa | Label asli | Catatan |
|---|---|---|---|---|
| A | UCI SMS Spam Collection (5.574) | EN | ham / spam | Spam ≠ phishing; baseline klasik |
| B | Mishra & Soni 2022, Mendeley `f45bkkt8pr` (5.971) | EN | ham / spam / smishing | Label smishing eksplisit; ~4.753 baris tumpang tindih dengan A |
| C | Dataset SMS Indonesia (Wibisono 2018 / turunannya) | ID | normal / penipuan / promo | Penipuan ≈ phishing; perlu dicek ketersediaan file |
| D | Smishtank Dataset I (~1.062) | EN | smishing saja | Opsional, tambahan contoh positif |

## Langkah
1. Download mentah ke `data/raw/<sumber>/` (jangan diubah) → verifikasi jumlah baris & label.
2. Mapping label ke biner: `phishing` = smishing/penipuan (+ spam? → keputusan di bawah), `aman` = ham/normal (+ promo?).
3. Gabung, buang duplikat (A∩B), simpan `data/processed/phishguard_sms.csv` (kolom: `text,label,lang,source`).
4. Split stratified train/test 80/20 dengan seed tetap.
5. Catat statistik + lisensi/sitasi tiap sumber di `data/README.md` (perlu untuk Proposal BAB III).

## Keputusan terbuka
- Spam/promo ikut kelas mana? Default usulan: **promo/spam = Aman-nya bukan, tapi bukan phishing** → opsi:
  (a) buang dari data biner, (b) masukkan ke Aman. Default: **(b) Aman**, karena promosi bukan penipuan, dan aplikasi
  hanya menandai penipuan. Dicatat di sini supaya bisa diubah.

## Hasil (2026-11-12) — **selesai**
- Dipakai: **B** (Mendeley, EN) + **C** = Rahmi & Wibisono 2016 (ID, 1.143 SMS, CC BY-SA 4.0, didapat dari mirror
  github.com/agustinustheo/indonesian-sms-spam-filtering, checksum cocok).
- **A** (UCI) diunduh tapi tidak dipakai: hampir semuanya sudah ada di B.
- Ditemukan dan **ditolak**: ekaputra07/ina-sms-classifier (20rb SMS laporsms) — tanpa lisensi, label berisik, tidak ada SMS normal, ada nomor HP pengirim.
- **D** (Smishtank) belum diambil — opsional kalau butuh contoh phishing EN tambahan.
- Keputusan spam/promo → **aman** dipakai.
- Output: `data/processed/{phishguard_sms,train,test}.csv` — 6.939 pesan, phishing ~12%. Detail & sitasi: `data/README.md`.

## Temuan penting untuk langkah berikutnya (model)
- Data tidak seimbang → akurasi saja menyesatkan (baseline "selalu aman" ≈ 88%). Evaluasi pakai F1/recall kelas phishing,
  pertimbangkan `class_weight="balanced"`. Usulkan revisi NFR-03 jadi mis. "F1 phishing ≥ 0,85".
- Data Indonesia kecil (335 phishing). Kalau performa di `lang=id` jelek, cari data ID tambahan.
